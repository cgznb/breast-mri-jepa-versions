# 当前复现协议：同一患者划分，各方法保留原论文输入

本协议依据用户进一步明确的要求制定，并取代此前将“统一三相ROI32适配”作为主对比的建议。原方案保留于 `history_before_native_input_policy/`。

## 固定患者与评估

- 使用当前976人队列的既有身份划分：801人开发、175人固定内部留出，留出阳性56人。
- 每个方法沿用同样的五折train/val/test患者归属；不另随机划分，不把验证或留出患者加入预训练。
- seed44；每个原生支持的预测时点先逐患者平均五折概率，再计算同一套指标。主阈值0.5；原文验证阈值可另列分析。
- 原文的训练步骤、监督目标、初始化和优化方案按方法记录；超参数与checkpoint只由验证集选择，数据依赖的归一化/插补/特征筛选仅在相应训练折拟合。
- 原文完整病例要求如导致实际可训练人数减少，保留原患者归属并列明实际分母及缺失原因，不能重新分配患者来凑人数。

## 按原论文准备网络输入

每个方法分别核验并冻结以下信息，不能仅把当前三相ROI32换个形状后当作原版输入：

1. MRI采集相位和相位时刻；early、late、peak的原始定义。
2. PE、SER、subtraction等派生图的公式、单位、分母、clip和有效区域。
3. 2D/3D结构、MIP方向、全乳或病灶视野、分辨率和输入尺寸。
4. 原文分割、habitat及动态几何的定义、生成方法和标注来源。
5. 原文临床变量与其他模态；不擅自添加我们的Arm或删除原文模态。
6. 原文访视组合、预测时点和原生缺失访视策略。

例如BSTNet应核验peak-enhancement、原文64×128×128病灶VOI及其时序/缺失处理；TemporalRL应核验PEearly/PElate/SER与原文2D MIP；STI应保留原文habitat和时间信息。论文与简化代码不一致时先列明差异，并按可核验的论文机制重实现，不默默简化。

保留原文归一化算法，但原研究队列拟合的均值、标准差等数值不直接套到新训练折；在本折训练患者上按同一算法重新估计并冻结。

## 按相同临床时点比较

固定同一批患者，并不允许把使用未来MRI的方法放进早期预测列：

- 原生只支持T0+T1的方法，在对应早期时点比较；不为填满三列而改写输入序列。
- 只报告已核实的原生预测时点；T0/T1/T2均支持时才计算相同三时点Macro，否则Macro记不可用。
- 需要术前T3的分类器保留其输入，但列为更晚信息参考，不能称为T0/T1/T2早期对手。
- 固定175人全部有T0/T1/T2，只有163人有T3。需要T3的方法须核验原文已有的缺失处理；不能默默剔除12人、任意插补，或把163人结果当作175人结果。无法满足固定队列要求时标为待补输入或不可完成该项比较。

TemporalRL已有原生早期读出的证据，不能笼统认定其只能四访视分类；BSTNet是否允许某种缺失及早期组合也应按原文逐项确认。详见逐方法原生输入审查。

## 分别准备各方法的数据

先按冻结ID盘点原始相位、随访mask、派生图和临床字段，再生成各方法所需数据。当前三相NPZ可用于身份与已有raw强度核对，但不能代替未保存的peak phase、全乳视野、原生多时点分割或其他模态。

当前每个NPZ的`roi`都是同一个T0预测mask，不是该访视的肿瘤真值；不能据此伪造动态体积或三类habitat。

影像重建按项目AGENTS约束，保持native metadata、mask header、registered geometry、相位/纵向变换与网格配套，不能混用修正后的public JSON和旧mask header。保留原始文件，在独立派生版本操作。

## 实施与报告

先完成原生输入规范和固定队列可用性清单；满足条件后准备原生数据，复核网络与训练方案，再测量资源和正式五折训练。缺少关键输入或实现细节时记录缺口，不产生冒名的简化结果。

ClinicalOnly、ResNet/GRU等控制仍保留价值；额外临床变量或统一输入版本作为独立补充实验，不替代原论文输入的主比较。

主表标注各方法实际相位/模态、临床变量、mask来源、可见时点、预训练和实际样本数。这评估的是各完整方法在同一测试患者上的表现；纯网络结构归因仍依赖额外控制和已有内部消融。

机器规则为 `native_input_policy.json`，计划为 `benchmark_plan.json`。本次只修订并核验协议，未启动正式训练或重建影像。
